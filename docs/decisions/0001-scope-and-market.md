# ADR-0001: 范围与市场选型

- 状态: 已接受
- 日期: 2026-06-19
- 决策者: 用户 + ZCode

## 背景

用户要构建自动化交易系统，最初需求较宽泛。需要先收敛范围，因为不同市场（加密/A股美股/期货/外汇）的数据源、交易接口、规则差异极大，会决定整个技术栈。

同时需明确 MVP 的功能边界：是只做信号/回测，还是要真实下单？这影响系统复杂度和风险等级。

## 决策

- **市场**: 仅 A 股。
- **MVP 功能范围**: 只做信号生成 + 回测，不真实下单。
- **数据源**: AkShare（默认，免费）+ Tushare（可选，需 token），可插拔。
- **编程语言**: Python ≥ 3.10。
- **策略类型**: 技术指标策略（MA/MACD/RSI/布林）。

## 理由

1. **A 股优先**: T+1、涨跌停、100 股整数倍等规则明确，回测自建成本可控；接口（AkShare/Tushare）免费且成熟，适合个人量化起步。
2. **信号+回测先行**: 真实下单风险高、需严谨风控与对账机制。先用回测验证策略有效性，再谈下单，降低风险。这也是个人量化最常见、最稳妥的起点。
3. **可插拔数据源**: AkShare 免费但偶有不稳定，Tushare 质量高但需积分。两者抽象为同一接口，互为备份。
4. **Python**: 量化生态最成熟（pandas/akshare/tushare/pandas-ta 原生支持），社区资源丰富。
5. **技术指标策略**: 最常见、最易懂，适合 MVP；架构上预留扩展到选股因子和 ML 策略的空间。
