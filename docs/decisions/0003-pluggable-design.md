# ADR-0003: 插件化设计哲学

- 状态: 已接受
- 日期: 2026-06-19
- 决策者: 用户 + ZCode

## 背景

用户在交互中多次强调可扩展性诉求：
- 数据源要"AkShare + Tushare 可插拔"。
- 技术指标要"建一个目录专门放固定格式的指标数据，后续可自己添加选股因子或技术指标条件"。
- 策略要可扩展。

这表明系统应统一采用插件化设计，而非把每类组件写死。

## 决策

**一切皆插件**。四类核心组件全部接口化、目录化、可自动发现：

| 组件 | 接口 (ABC) | 目录 | 自动发现 |
|------|-----------|------|---------|
| 数据源 | `DataSource` | `autotrade/datasources/` | ✅ `__init__.py` 扫描注册 |
| 指标 | `Indicator` | `autotrade/indicators/` | ✅ |
| 策略 | `Strategy` | `autotrade/strategies/` | ✅ |
| 报告 | `Reporter` | `autotrade/reporters/` | ✅ |

**实现约定**:
1. `core/interfaces.py` 定义所有 ABC，核心层只面向接口编程。
2. 每个插件目录的 `__init__.py` 用 `importlib` 自动扫描本目录所有模块，符合接口的类注册到 `registry`。
3. **新增插件 = 往目录加一个文件**，无需改任何注册代码（符合"放目录里自己加"的诉求）。
4. 指标输出固定列名格式 `ind_<name>_<field>`，保证策略和前端能稳定按列名取值。
5. 策略参数与代码分离（`config/strategies/*.yaml`），改参数不改代码。

**回测引擎(Backtester)是例外**: 它不是插件，因为 A 股撮合规则（T+1/涨跌停/手续费）是硬约束，不应被替换；但通过 `BacktestConfig` 参数可配置。

## 理由

1. **统一风格**: 三类插件用同一套注册/发现机制，降低认知负担。
2. **零侵入扩展**: 用户加新指标/策略/数据源时，核心代码零改动，符合"可自己添加"的诉求。
3. **可测试**: 每个插件独立实现接口，可单独 mock 测试。
4. **前端友好**: 自动发现 + YAML 参数化，前端只需改配置/传参即可调度任意插件组合。
